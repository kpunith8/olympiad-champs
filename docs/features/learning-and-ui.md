# Learning, content rendering and UI

Status: proposed; visual identity is not approved. See [design plan](../design-plan.md) for the design validation process.

- Learners choose class → subject → Learn, Practice or Test. Explain each mode and show saved progress, availability and a clear next action. Support independent use, with optional parent help, across a wide age range.
- Teach with short concept explanations and ordered worked steps describing what and why. Keep the relevant formula or diagram near each step. Let learners revisit or skip support; do not equate viewing with mastery. Practice gives supportive feedback; test explanations wait until submission.
- Use legible text, semantic controls, visible focus, keyboard/touch access, reduced motion, responsive layouts and meaningful error/empty/save states. Target WCAG 2.2 AA; aim for 44 × 44 CSS-pixel primary touch targets where practical. Never convey meaning only by color or sound.
- Use structured blocks and a restricted Markdown/LaTeX subset; no arbitrary executable HTML, scripts or author-provided SVG. Validate and sanitize input and asset paths. Prototype MathJax with `remark-math`, checking accessibility and performance; compare KaTeX before selecting. Use validated structured data and trusted SVG components for fixed diagrams, including shape sequences, figure grids, arrows and clocks; formulas use math rendering, not SVG drawing commands. Check shape positions, fills, counts and clock hands against the question and answer. Provide neutral descriptions that do not reveal the answer and keyboard-accessible choices. Use reviewed static assets for complex one-off visuals; avoid AI-generated precision-critical diagrams. Evaluate JSXGraph only for interactive geometry and test accessible alternatives.
- Keep small, rights-cleared images in `public/` initially. Text may be imported into Neon through a reviewed versioned publishing process; the source of truth is undecided. Defer blob storage until its costs and access needs are clear.
- Validate representative content on mobile and desktop, including long passages, equations, diagrams, screen readers, offline/failure states and actual learners in different age groups. Do not invent endorsements or official affiliation.

References: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [MathJax accessibility](https://docs.mathjax.org/en/latest/basic/accessibility.html) · [remark-math](https://github.com/remarkjs/remark-math) · [sanitization](https://github.com/rehypejs/rehype-sanitize) · [JSXGraph](https://jsxgraph.org/docs/).
